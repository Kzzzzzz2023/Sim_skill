# 调试与性能

## 先区分问题所在

| 现象 | 可优先检查 |
| --- | --- |
| 构建、加载或调用失败 | 本地依赖、接口声明、库路径、构建入口与并发调用约定；先区分环境故障和模型故障 |
| 功能输出错误 | 指令效果、动态值采样、真实访存数据、部分完成、身份复用与同步；不靠调整周期掩盖 |
| 挂起或提前结束 | 在途队列、重试、credit、定时完成与唤醒；无退休或事件队列耗尽不等于程序完成 |
| 周期明显不符 | 计数范围、实际接受、仲裁、容量、返回顺序、回压和释放边界，再考虑延迟参数 |

开发与测试可按问题交替进行。已有正确部分不必重做；具体测试粒度和停止条件由任务决定，而不是固定循环。

## 时序定位

有本地参考时，先统一输入、配置、初始化状态、时钟单位与计数起止，再比较发射、接受、服务、缺失、填充、返回和写回等共同边界。寻找能够解释后续偏差的最早差异；不同抽象层不必逐拍一一对应。未经确认的复位前事件或不同统计窗口不直接作为误差依据。

没有细粒度参考时，可用依赖链与独立指令流区分延迟和吞吐，用 bank 冲突、缺失合并、输出阻塞和同步小程序检查资源关系。占用与停顿记录用于形成假设；仅有单个正确结果或平均周期接近，不能证明结构正确。

大输入或最差用例用于发现问题，不用于按名称选择模型或拟合专属周期乘数。先修正缺失的竞争、采样和排序，再考虑聚合延迟校准。局部改动验证后，以受影响路径和更广输入检查回归；保留尚未解释的偏差。

## 降低模拟成本

**先判断在减少什么工作。** 流水或事务抽象减少需要模拟的内部动作，可能改变周期；减少复制、分配、查询和调用则属于实现优化。纯实现变化应保持原模型行为，可比较结果、周期/指令计数及关键事件；总周期相同不单独构成等价证据。

**沿用现有观测设施。** 用本地热点分析和运行计数找主要成本，报告、快照及详细跟踪按需生成。先减少重复状态和跨层临时对象，再考虑紧凑存储、复用和缓存；小而有界的扫描不一定比维护活动集合慢。

**明确复用有效期。** 同步借用的数据不应被跨拍持有；缓存应有明确失效条件；软件对象池不能意外成为新的硬件容量限制。局部优化没有稳定端到端收益时可以撤回，不因少一次分配就默认保留。

**区分门控、批量与跳时。** 没有请求或退休指令，仍可能有定时完成、控制等待、刷新或其他维护事件。减少跨语言调用可以保留内部每个逻辑时钟；只有相关模型明确支持安全的下一事件推进，才考虑跳过时间区间。批量边界还需覆盖新请求提交、回调和关闭排空。

## 判断结果

功能正确、周期精度和宿主速度分别报告。时间影响控制流的程序单独检查工作量与失败原因，不隐藏失败，也不混入普通等工作量测速。平均误差之外关注尾部、新输入和资源变化趋势；详细参考本身也可能有误差。

测速使用明确的代码、输入和环境，以重复配对结果判断；区分初始化、模拟区间与完整进程耗时。插桩开销、累计 CPU 占比、调用次数下降不能直接换算真实耗时收益。

编译优化、垃圾回收、宿主线程数及绑定策略只在任务允许范围内实测，不改变模拟硬件配置。每次模型修正后重新建立实现优化的比较基线；出现功能或精度退化时再回到对应问题，不强制每轮从头执行所有阶段。
