# 构建与框架复用

## 构建骨架

以下概括常见组成及依赖，不规定类名、文件布局或强制阶段。小程序和局部测试可随组件接入，不必等系统完成。

| 组成 | 建模重点 | 可优先复用的本地设施 |
| --- | --- | --- |
| ISA 与架构状态 | 覆盖目标配置的指令、寄存器与控制语义，验证逐指令效果 | 已有译码、运算支持、浮点封装、加载器与测试 |
| 计算单元 | 整数、乘除、浮点、控制及访存资源；延迟、启动间隔、在途与输出限制 | 已验证的运算实现、队列与服务机制 |
| 流水线与依赖 | 取指、译码、发射、读操作数、执行和写回；相关性、bank/端口冲突与回压 | 时间引擎、缓冲、消息与事件机制 |
| 调度与并发 | 可发射条件与仲裁；适用时加入多 warp、分歧汇合、同步与驻留 | 现有调度接口和状态容器，策略依据目标选择 |
| 访存路径 | LSU 地址、lane/字节掩码、合并、局部存储、I/D-cache、缺失与返回 | 兼容的 cache、数据阵列、缺失跟踪与互连组件 |
| 外部存储 | 请求接受、排队、返回、时钟换算及排空 | 预置时序存储后端及其接口封装 |
| 系统执行 | 程序或 kernel 启动、线程组分配、完成通知与输出可见性 | 现有运行接口、驱动、构建和测试入口 |

可先闭合简化执行路径，再接入更多资源和层级。系统接口可提前对接；通信桩通过仅说明接口可达，不说明模型已执行程序。任务没有要求的层级、扩展或多核机制无需补造。

## 复用的粒度

**通用机制优先沿用。** 时间推进、端口通信、队列、观测钩子、运算支持和程序运行工具通常不需要重写。先查已提供的依赖及封装，再决定新增内容；不要仅因 Skill 提到某种能力就假设环境已具备它。

**硬件组件按语义选择。** 接口能连接不代表模型匹配。cache、调度与互连要核对容量、仲裁、地址映射、缺失合并、重放、替换和可见性。可以只复用其中的数据阵列或容器，保留目标特有的控制；不为适配现成组件而改变目标资源。

**框架负责推进，模型负责行为。** 按独立状态、交互与替换需求划分组件。Core、cache、互连之间适合显式端口；紧耦合的内部流水级可在一个组件内推进，不必每拍每级都进入全局事件队列。已有引擎可用时，无需为局部优化重写整套调度器。

## 时间与通信

明确发送尝试、实际接受和完成的区别。发送失败时保留请求，按端口约定重试；等待接收、服务和回调的身份保持一致，避免重复提交。框架传输延迟、适配层延迟和硬件延迟分别核对，防止重复计时。

统一时间单位、时钟倍率和同时间戳的可见顺序。局部周期推进可分离旧状态决策与状态更新，也可采用等效的事件安排；关键是软件调用顺序不能意外引入同拍穿透或额外停顿。

按需推进只减少无效调用，不免除唤醒责任。组件等待时，应有消息到达、端口可用、内部到期或控制变化等明确唤醒来源；是否重新调度以本地引擎约定为准，不把“本拍无进展”直接当作完成。

## 外存与运行边界

先核对预置存储后端是否同时维护数据和时序。若它只提供请求身份与完成事件，模型侧仍需负责字节、掩码及约定边界上的读写生效；控制器接受写入的确认未必表示物理写入排空。

适配层承接容量、接受与返回带宽、排序及回压，但不重复实现后端已有的服务时序。核对回调线程、并发调用和实例生命周期；跨次启动是否保留内存、cache 或外存状态，由本地接口约定决定。

执行结束、请求排空和宿主读取到正确输出应分别理解。已有驱动和测试入口尽量沿用，不扩大模型职责，也不以替换运行工具或参考输出来掩盖未实现行为。
