# 构建骨架与复用

## 常见组成

下表是依赖关系参考，不规定类名或强制阶段。小程序与组件测试随接入开展，已有正确部分无需重做。

| 组成 | 建模重点 | 优先复用的本地设施 |
| --- | --- | --- |
| ISA 与架构状态 | 目标配置内的指令覆盖、寄存器、控制与内存效果 | 已有译码、运算和浮点封装、加载器及测试 |
| 计算单元 | 整数、乘除、浮点、控制和访存资源；延迟、启动间隔、在途与输出限制 | 已验证的运算实现、队列与服务机制 |
| 流水线与依赖 | 取指、译码、发射、读操作数、执行、写回；相关性、bank/端口冲突与回压 | 时间引擎、缓冲、消息和事件机制 |
| 调度与并发 | 可发射条件与仲裁；适用时加入多 warp、分歧汇合、同步和驻留 | 调度接口、状态容器及可匹配组件 |
| 访存层级 | LSU 地址与字节掩码、合并、局部存储、I/D-cache、缺失及返回 | 兼容的 cache、数据阵列、缺失跟踪和互连 |
| 外部存储 | 请求接受、排队、数据生效、返回顺序和时钟换算 | 预置时序后端及接口封装 |
| 系统执行 | 程序或 kernel 启动、线程组分配、完成通知与输出可见性 | 运行接口、驱动、构建和测试入口 |

可先闭合简化执行路径，再加入层级和竞争；最终需要哪些细节由任务决定。接口可以提前对接，但通信桩通过只说明接口可达，不说明模型已执行程序。多核、地址转换、一致性等按范围加入，不把它们默认列为单核闭环的前提。

## 组织状态，而不是复制层次

一种轻量组织是区分静态配置、架构状态、动态指令/事务、资源状态和观测结果。配置描述目标能力；架构状态保存已可见值；动态记录持有本次采样值与尚未交付的效果；资源状态表达占用和仲裁；报告从这些状态生成。可组合在同一组件中，不要求各建一层框架。

每类可写状态尽量有清楚的所有者。时序队列可携带紧凑身份和必要路由信息，引用同一份动态语义记录，避免不同流水级各保留一份完整寄存器快照。小值直接传递与句柄间接引用各有代价，无需为统一形式引入复杂对象管理。

按独立资源竞争、时钟域、数据所有权及替换需求划分组件。跨组件通过端口或窄接口连接；紧耦合逻辑可留在组件内部。静态参数可在构造时解析，没必要为读取参数而每拍遍历结构说明或生成资源清单。

## 本地复用的选择

先分清环境已经提供了什么：运算支持、字节存储、时间引擎、消息设施、完整硬件组件，还是仅有接口封装。基础库可用不等于目标计算单元或 cache 已完成；声明了框架依赖也不保证离线包包含所有组件。

通用机制优先沿用。硬件组件则核对地址映射、容量、带宽、仲裁、缺失处理、写策略和可见性。语义匹配时配置使用；局部不同可包装、替换策略或复用内部数据结构；无法表达研究对象时再自建必要部分。不要让适配层重复计入已有队列容量或服务延迟。

系统组装、时间与端口的具体使用见[基础设施使用](infrastructure-usage.md)。复用的价值是减少非研究部分的重建，不是增加类型依赖或强迫所有内部状态消息化。

## 运算和数据表达

功能效果尽量只有一套定义，时序层决定采样与交付。浮点支持还应核对舍入、异常标志及封装的并发约定，不以宿主普通浮点运算静默替代目标语义。

寄存器和传输数据可用定宽位模式或明确类型的值承载，在运算边界解释整数/浮点。位重解释不同于数值转换；不要仅为展示方便在热路径中反复转换。访存边界上的宽度、字节序、符号扩展和有效字节由目标决定。数据布局可以优化，但不改变值的语义。

## 外存与系统接入

核对预置外存模型是否同时维护数据和时序。若它只提供接受与完成事件，模型仍需保存字节和掩码，并在约定边界采样读值、应用写入。接受进入本地发送缓冲、外存接受、回调和物理排空可能不同，不凭接口名称推定。

运行接口可薄封装已有模型：加载与访问内存、启动、查询、等待和错误回传。重复运行时，哪些内存、cache、外存和调度状态保留，哪些在重置时清除，按接口约定区分。预算耗尽可续跑时保留在途身份和时间，不把下一次调用当新启动。

硬件执行结束、上下文可回收、请求排空与宿主可见输出应分别判断。宿主完成线程与模拟推进的并发需要在接口边界协调，不以宿主线程调度顺序决定模拟时间；已有运行工具和测量窗口尽量沿用。
