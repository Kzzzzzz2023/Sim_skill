# 基础设施使用

本页说明组件式、事件驱动基础设施的常见使用方式，不假定当前环境包含全部能力。`Engine`、`Component`、`Port`、`Connection`、`Builder`、`Tick` 等词仅供检索本地接口；具体签名与通知行为以预置版本为准。

## 先确认可用层次

区分依赖声明、实际源码、可链接库和已接线组件。离线依赖可能只裁剪保留已用子包；有时间引擎不意味着 cache、互连、监测界面或代码生成工具都可用。优先沿用本地封装和测试，缺失功能不通过下载解决，也不把不可用组件当作完成项。

版本差异常影响时间类型、事件处理器注册、发送是否返回错误、组件构造和端口归属。理解所需接口即可，无需先通读框架。已有兼容组件优先复用；不要为模仿某种组织方式另起一套框架。

## 组装与组件粒度

可在构造层集中配置引擎、频率、容量、组件实例、端口连接和地址路由；热路径只处理已解析的状态。采用值式配置接口时保留配置方法返回值，避免设置没有进入最终实例。

组件与事件处理器身份应在同一运行域内可区分；端口名称、归属和目的地要对应实际连接。多实例不宜共用可写全局状态。上层组合只暴露必要端口，避免跨层直接修改内部队列，否则可能绕过容量检查和唤醒。

独立缓存、互连和不同时钟域适合显式组件。单个核心内紧耦合的发射、执行和写回，可由一个组件推进内部资源；不必每个寄存级一个全局事件。组件分开是为了表达边界，不是越多越接近硬件。

## 引擎与局部推进

| 工作特征 | 可考虑的组织 | 需要留意 |
| --- | --- | --- |
| 每拍都有多处紧耦合活动 | 一个组件内局部逐拍求值 | 同拍可见顺序及边界回压 |
| 长时间等待，唤醒来源明确 | 到期事件或按需 Tick | 内部完成和控制变化不能漏唤醒 |
| 独立子系统交互较稀疏 | 全局事件连接局部执行域 | 时间换算、跨域到达与确定性 |

局部直接推进与复用框架可以共存，但应明确谁拥有模拟时间。若外层引擎还管理其他组件，局部批量不能越过下一次可能影响它的外部事件，也不能随后向引擎过去的时间提交消息。不同时让两个入口推进同一外存或资源。

同时间戳事件的处理顺序不自动等于硬件边沿。框架可能以普通/后置事件分开组件计算与消息交付；使用现有约定或等效边界，避免因组件调用顺序出现同拍穿透。名为“零延迟”的连接仍可能涉及排队和下一次 Tick，不能只看参数推断端到端周期。

复用按实际职责判断：时间引擎负责调度、通信组件负责传输、硬件组件负责其资源行为。仅导入依赖或借用时间类型不等于已使用其引擎或 cache。若任务指定框架使用范围，不因局部优化而绕过该要求。

## 端口、接受与回压

发送成功常常只表示进入本地发送缓冲，不代表目标硬件已经接受，更不代表服务完成。可区分创建、入发送队列、到达接收队列、服务接受和返回消费，用于明确延迟和所有权；只保留任务需要的观测边界。

本地接口可能要求先用 `CanSend` 一类检查再发送，满队列发送会异常；也可能由发送操作返回失败。不要混用两种假设。接收时先查看队首，确认有接纳能力，再取出消息；取出后等待也可以，但应有明确的有限存储接管请求。

输入队列、输出队列和连接中的缓冲是否对应硬件容量，需要显式解释。缓冲深度不是每拍带宽；一些直连会一次转发所有可送消息，不能默认它实现了目标的端口限制。发送率、服务率、返回率分别由对应组件约束，避免在每层重复限速。

背压期间保留原请求身份、数据与已接受的子请求状态；不能每次重试都新建逻辑事务。请求发出后，除非协议允许，不修改接收方仍会使用的载荷。响应到达也可能等待下游消费，需保持稳定而非重复应用效果。

## 按需 Tick 与唤醒

`Tick` 的进展返回值用于决定是否继续调度，不是退休指令数，也不是模型完成标志。未发射时仍可能有流水移动、仲裁游标变化、倒计时、同步释放或存储尾部。常见等待方式如下。

| 等待原因 | 恢复推进的依据 |
| --- | --- |
| 等待新请求或响应 | 接收通知 |
| 发送队列满 | 端口释放或连接可用通知 |
| 等待内部结果到期 | 保持必要 Tick，或显式安排到期唤醒 |
| 等待依赖、同步或控制条件 | 条件的生产者通知，或受控重新检查 |
| 当前候选无事可做但仲裁仍会变化 | 继续推进有效调度状态，不以一次空发射休眠 |

通知可能只在空变非空、满变非满等转变发生，不一定每条消息都触发。消息留在队列而组件睡眠时，必须仍有重新激活的来源；同理，单纯改变一个内部标志不保证框架自动通知。重复唤醒应遵循框架的 Tick 去重机制。

聚合多个子步骤的进展时，每个必要步骤都要被调用。不要写成先检查累计 `progress` 再以短路逻辑调用下一步骤，否则前一步成功会跳过后续工作。先执行各步骤，再合并返回值即可。

跳过无活动区间时，用实际经过时间更新需要保留的计数和到期状态；统计调用次数不能代替模拟周期。初始化、注册就绪信号或控制等待尚未稳定时，空队列也不必然是可跳过的静止点。

## 复用 cache、互连与存储组件

先核对配置单位：总容量还是每 bank 容量、字节还是 word/line、延迟属于哪段、带宽按请求还是字节计。再核对写策略、替换、MSHR 及等待者计数、填充与重放占用、非缓存路径和 flush。字段同名不保证语义相同。

可复用整组件，也可只复用数据阵列、目录、缓冲或地址路由；用窄适配层补协议差异。复用数据容器不意味着它已实现冲突时序。已有外存模型负责服务时序时，适配层只补缺少的接纳、排序、返回与数据边界，不再叠加同一段延迟。

## 观测、测试与运行结束

优先使用已有 hook/trace 机制，在创建、接受、服务和完成等位置关联请求及父子身份。保留少量占用、停顿和完成计数，按问题启用局部事件或窗口；避免生产 Tick 总是构造完整报告。离线文件或内存观察即可，不把外部服务或可视化界面设为构建依赖。

局部组件测试可用有限请求源、可控延迟后端和故意阻塞的接收端；另用小型真实连接测试验证通知和时间顺序。只测方法返回值无法覆盖事件注册、首次唤醒和背压恢复。

确认事件处理器中的错误能传到运行入口；某些引擎可能不传播处理器的返回错误，需要模型保留失败状态并停止后续推进。事件队列耗尽只说明没有已安排事件：应再区分正常完成、仍有未唤醒工作和失败。运行到预算上限也不一定把引擎时间推进到该上限，续跑以实际时间和待处理事件为准。

宿主并行不等于模拟并行。可先用串行推进获得容易定位的行为，再按组件隔离和实测成本考虑并行；宿主线程间的锁只保护共享状态，不能替代模拟时间、仲裁或消息顺序。
