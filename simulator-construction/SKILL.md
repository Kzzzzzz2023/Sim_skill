# 模拟器构建与抽象参考

本文提供候选方法，不替代任务目标、目标硬件证据与本地接口约定。根据已有工程和验证结果选择构建顺序、组件粒度与抽象程度；不要求先完成详细模型再构建快速模型，也不要求固定的角色或迭代轮次。

## 使用边界

只使用任务允许的工作区、只读参考和预置依赖。基础设施复用指复用这些可用资源，不指寻找其他工程或联网安装。具体 API 从本地接口声明、允许读取的源码、示例和测试确认，不凭其他版本的记忆调用。

缺少必需工具或依赖时说明缺口，不改写冻结环境或静默替换验收后端；任务允许简化实现时，区分临时接口与最终模型。修改范围与运行入口遵循当前任务，而不是本 Skill 中的例子。

## 基本构建路线

```text
目标配置内的完整 ISA 与架构状态
  → 计算单元与资源约束
  → 流水线、依赖与调度
  → LSU、合并、cache 与局部存储
  → 外部存储与系统执行
  → 功能调试、时序修复与实现性能优化
```

这是一条依赖关系参考，可以交叉推进。ISA 无需在此重学；已有实现先验证复用。简单访存后端可用于早期闭环，但最终范围由任务决定。非 GPU 目标无需引入 warp、线程组等结构。

## 核心判断

**先复用，后自建。** 优先配置或适配已提供的时间引擎、通信机制、运算支持、存储和运行工具；现成组件不满足目标行为时，再局部扩展或自行建模。

**模拟因果，不复制外形。** 保留影响容量、竞争、接受、采样、顺序、回压与可见性的状态；不必为每个 RTL 模块和寄存级创建软件对象。

**区分模型与实现。** 抽象可能改变周期预测；纯实现优化应保持原模型行为。执行单元变快与宿主代码变快不是同一件事。
