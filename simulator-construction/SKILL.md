# 模拟器构建与抽象参考

按目标架构、任务范围、已有工程和验证结果选择方法。以下内容不替代目标硬件证据、本地接口或验收要求；不要求先建详细模型再建快速模型，也不规定角色、文件结构或强制迭代轮次。

## 使用边界

只使用任务允许的工作区、只读参考和预置依赖。复用指利用这些资源，不指联网寻找其他实现。具体 API 从本地声明、允许读取的源码、示例和测试确认；声明依赖不等于所有子包都已提供。

必需设施缺失时说明缺口；任务允许简化时区分临时后端和最终模型，不静默替换验收后端、不改写冻结环境。本 Skill 的候选方法不扩大任务权限或模型范围。

## 构建路线

```text
目标范围内完整 ISA 与架构状态
  → 计算单元与资源约束
  → 流水线、依赖、调度与并发控制
  → LSU、合并、cache、局部存储与外部存储
  → 程序或 kernel 的系统执行闭环
  → 功能调试、时序修复与实现性能优化
```

这是依赖关系概览，可以交叉推进；已有实现先验证复用，系统接口和局部测试可提前接入。ISA 无需在此重学，非 GPU 目标无需引入 warp 或线程组。

## 核心判断

**复用机制，核对模型。** 时间引擎、通信、运算和运行工具优先沿用；cache、调度等硬件组件还要检查语义是否匹配。按需配置、适配、局部扩展或自建，不为套框架改变目标行为。

**保留因果，压缩搬运。** 重点表达容量、竞争、接受、采样、顺序、回压和可见性；资源到期不等于写回，指令退休不等于副作用结束。不以 RTL 对象数量衡量模型质量。

**按成本选粒度。** 跨组件可用事件和端口，紧耦合内部可局部逐拍推进；复用框架不要求每个寄存级都调度事件。结构抽象、纯实现优化与宿主参数调整分开判断。
